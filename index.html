HOW I SOLVE PROBLEMS

A disciplined four-step engineering sequence for handling complex storefront challenges.

01

Understand

Study the existing system, merchant workflow, data flow, and hard platform boundaries first.

↓
02

Preserve

Keep what already works well natively (Metafields, native sections) to minimize maintenance cost.

↓
03

Improve

Extend native capabilities with lightweight client code or targeted Storefront API calls.

↓
04

Replace

Replace only what is fundamentally broken or causing severe technical debt & page slowdown.

SYSTEM DECISION ENGINE SIMULATOR Select a decision branch to inspect strategy
STRATEGY: PRESERVE NATIVE

Preserve Working Platform Fundamentals

When existing native features (like Shopify Customer Metafields or theme sections) already solve 80% of the problem, do not introduce extra databases or paid apps. Preserve native capabilities to minimize ongoing maintenance cost.

SELECTED WORK

Real-world technical case studies structured by Problem → System → Investigation → Implementation → Result.

REAL PROBLEM #01 · PUBLIC REPOSITORY

figclaw

Direct API bridge connecting Claude AI to Figma before official MCP support.

01 / REAL PROBLEM

Figma lacked a direct bridge to pass design context and vector tokens directly to Claude AI for automated frontend code generation.

↓
02 / EXISTING SYSTEM

Developers had to manually copy-paste Figma inspect data and CSS properties into prompts line-by-line.

↓
03 / INVESTIGATION

Analyzed Figma REST API endpoints and node graph structures to extract exact layout geometries programmatically.

↓
04 / IMPLEMENTATION

Engineered a lightweight Node.js/JS execution script linking Figma node trees directly to Claude Code.

↓
05 / RESULT

Automated design-to-code context passing, eliminating hours of manual inspection friction.

REAL PROBLEM #02 · PUBLIC CHROME EXTENSION

Limit_Tracker

JavaScript Chrome Extension tracking API usage limits across AI services.

01 / REAL PROBLEM

Developers using multiple AI platforms faced sudden rate limits without a single unified usage monitor.

↓
02 / EXISTING SYSTEM

Each platform hidden usage metrics inside deep settings submenus or header responses.

↓
03 / INVESTIGATION

Inspected API response headers across Perplexity, Grok, Claude, Gemini, and DeepSeek.

↓
04 / IMPLEMENTATION

Built a client-side Chrome Extension (Manifest V3) parsing active session rate limits live.

↓
05 / RESULT

Unified rate limit visibility across 5 major AI providers in one browser popup.
